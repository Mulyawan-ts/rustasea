# [GAP-031] Missing 500-Line File Limit Linter Enforcement in CI and xtask

### 1. Context & Analysis

- **Trigger**: 
The project enforces a hard 500-line limit per source file as a maintainability standard, documented in an architecture decision record and repeated in the coding standards. Nothing in the build or CI actually checks the limit, so a file can grow past 500 lines and merge without any gate failing. A rule that is not enforced is a preference, not a standard.

- **Observation**: 
`docs/adr/ADR-0009-fsd-500-line-exception.md` records the 500-line standard and grants a documented exception: `.agents/documents/requirements/fsd.md` is 516 lines and is explicitly exempted. The ADR states at `:29` that "line-count linters must exempt it" and at `:39` that "a naive repo-wide line-count check will flag `fsd.md`; it must exclude this ADR-documented file". The standard is also referenced by `ADR-0010:30`, `ADR-0011:15`, and `docs/adr/README.md:19`. However, no enforcement exists. `xtask/src/main.rs` (102 lines) dispatches only `ci`, `fmt`, `clippy`, `check-cycles`, `deps:check`, `migrate`, and `docker:up`/`docker:down`/`docker:logs`; the unknown-task error at `:50` lists exactly that set, and there is no `lines:check` task. The CI workflow `.github/workflows/ci.yml` runs `quality` (`cargo xtask ci`), `test`, `deny`, `audit`, and an msrv job; none of them count file lines. The `run_ci()` sequence in `xtask/src/main.rs:59-90` runs fmt, clippy, deps:check, and cycles only. Consequently files in `crates/` can silently exceed 500 lines.

- **Goal**: 
Add a `lines:check` subcommand to `xtask` (optionally included in `cargo xtask ci`) that verifies every source file in `crates/` stays within 500 lines, honouring the ADR-documented exemptions such as `.agents/documents/requirements/fsd.md`, and wire it into CI so the limit is enforced.

### 2. Step & Implementation

1. Add a `lines` module under `xtask/src/` that walks the checked scope (`crates/` and the repository root as configured), counts lines per file (`wc -l` semantics), and reports any file above 500 lines.
2. Encode the exemption list in one place: exempt `.agents/documents/requirements/fsd.md` per `ADR-0009`, and make the list extensible so future ADR-granted exceptions can be added without editing the walker.
3. Register a `lines:check` task in `xtask/src/main.rs` dispatch and extend the unknown-task error string at `:50` to include it.
4. Add `lines:check` to `run_ci()` at `xtask/src/main.rs:59-90` so `cargo xtask ci` fails on a violation; confirm the ordering keeps the fastest checks early.
5. Update `README.md` (xtask surface description at `README.md:433` and `:511-523`) and `CONTRIBUTING.md` (created under GAP-028) to list `lines:check`.
6. Ensure the walker exits non-zero with a clear per-file report listing path and line count when a violation is found.

### 3. Acceptance & Verification

- **Checklist**: 
  - [ ] `xtask lines:check` exists and reports violations with path and line count.
  - [ ] The check passes on the current tree and fails when a file is deliberately grown past 500 lines.
  - [ ] `.agents/documents/requirements/fsd.md` is exempt and does not trigger a failure.
  - [ ] `cargo xtask ci` includes the check and fails on a violation.
  - [ ] `.github/workflows/ci.yml` runs the check transitively through `cargo xtask ci`.
  - [ ] Documentation lists `lines:check` in the xtask surface.

- **Testing**: 
  - [ ] Run `cargo xtask lines:check` on the reconciled tree and assert exit code 0.
  - [ ] Temporarily add a test file over 500 lines, run the check, assert non-zero exit and that the offending path is reported, then remove the file.
  - [ ] Confirm `fsd.md` at 516 lines does not appear in the violations output.
  - [ ] Run `cargo xtask ci` and confirm the new step executes as part of the sequence.
