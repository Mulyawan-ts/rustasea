# [GAP-029] show:model Command Remains a Non-Introspecting Placeholder

### 1. Context & Analysis

- **Trigger**: 
`show:model` was promised in milestone M1 as a model-introspection command that would surface schema and relationship information. The command is registered and runnable, but its implementation only prints the source file path and a derived table name; it does not inspect anything. The command therefore looks complete from the command surface while delivering none of the promised introspection.

- **Observation**: 
`crates/rustasea-cli/src/commands/inspect.rs:104` defines `ShowModel`, and its run path at `:124-141` performs no database or metadata inspection. It prints three things only: `model: {name}`, `file: app/models/{snake}.rs` (a computed path), and `table: <name>` derived from `Model::table_name()`. It does not read database columns, column types, relations, casts, hidden attributes, or timestamps. The M1 milestone documents `show:model` as part of CLI introspection, and `docs/milestones.md:96` lists it under M1 status, while `docs/milestones.md:108` correctly notes it "emits placeholder output" (`crates/rustasea-cli/src/commands/inspect.rs:67`). The module doc at `inspect.rs:1-4` ties the command to FR-109 and notes that both `route:list` and `show:model` honour `--json`. The tests at `inspect.rs:144-274` cover `route:list` rendering but do not assert any model-schema output beyond the placeholder.

- **Goal**: 
Either implement real model schema inspection for `show:model` (columns, types, nullability, relations, casts, hidden attributes, timestamps, honouring `--json`), or, if implementation is deferred, document `show:model` as a roadmap enhancement item with a dedicated task specification and correct the milestone status so it is not implied to be complete.

### 2. Step & Implementation

1. Decide the path: implement inspection now, or defer with a tracked specification. Record the decision in the task and, if deferred, in `docs/milestones.md`.
2. If implementing: extend `ShowModel` to resolve the model's table metadata through the ORM, then render a schema table (column, type, nullable, default) plus relations, casts, hidden attributes, and timestamps. Reuse the rendering helpers already used by `route:list` (`output::table`), and honour `--json` for a machine-readable form.
3. If deferring: add an entry to the roadmap or a dedicated enhancement task capturing the objective, the required introspection fields, the ORM APIs to use, and the `--json` contract.
4. Correct `docs/milestones.md:96` and `:108` so the status reflects reality: either implemented with evidence or explicitly deferred, without the "placeholder" wording left ambiguous.
5. Add tests: if implemented, assert column/relation output for a known model and assert the `--json` shape; if deferred, leave the existing placeholder tests and reference the enhancement task.

### 3. Acceptance & Verification

- **Checklist**: 
  - [ ] A decision (implement or defer) is recorded and reflected in `docs/milestones.md`.
  - [ ] If implemented, `show:model` outputs columns, types, nullability, relations, casts, hidden attributes, and timestamps.
  - [ ] If implemented, `--json` returns a stable, documented shape.
  - [ ] If deferred, a task specification exists and the milestone status is corrected.
  - [ ] Documentation no longer implies `show:model` is a finished introspection command.

- **Testing**: 
  - [ ] Run `cargo artisan show:model <name>` against a known model and assert the schema fields appear; if deferred, assert the placeholder output is unchanged.
  - [ ] Run with `--json` and assert the output parses as JSON and contains the documented keys (if implemented).
  - [ ] Run `cargo test -p rustasea-cli` and confirm the `inspect.rs` tests pass.
