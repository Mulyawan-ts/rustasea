# [GAP-024] README Command Surface Omits ADOPT Commands

### 1. Context & Analysis

- **Trigger**: 
`README.md` presents itself as the primary entry point for the framework and maintains an Artisan Command Reference, but the documented surface lags the implemented CLI. Commands delivered by the ADOPT program and the module system are absent from the reference, so users cannot discover `mcp:serve`, `tinker`, `lang:check`, `log:show`, the `module:*` commands, or the newer generators without reading the source.

- **Observation**: 
`crates/rustasea-cli/src/commands/mod.rs` registers 38 commands in `register_all_into`: 17 `make:*` generators, `list`, `module:list`, `module:enable`, `module:disable`, `route:list`, `show:model`, `openapi:generate`, `queue:failed`, `queue:retry`, `queue:work`, `schedule:list`, `schedule:pause`, `schedule:resume`, `schedule:run`, `migrate`, `migrate:fresh`, `migrate:rollback`, `lang:check`, `log:show`, `tinker`, and `mcp:serve` (feature-gated behind `#[cfg(feature = "mcp")]` at `crates/rustasea-cli/src/commands/mod.rs:60-61`). That is 37 commands by default plus one feature-gated command.

`README.md:125`, `:170`, and `:505` document only the older subset (`make:*`, `route:list`, `migrate`, `tinker`). Missing or under-documented: `mcp:serve` (ADOPT-015, `crates/rustasea-cli/src/commands/mcp_serve.rs:62`), `tinker` CLI details (ADOPT-008, `crates/rustasea-cli/src/commands/tinker.rs:43-45`), `lang:check` (ADOPT-005, `crates/rustasea-cli/src/commands/langcheck.rs:106`), `log:show` (ADOPT-014, `crates/rustasea-cli/src/commands/log_show.rs:74-84`), `module:list`/`module:enable`/`module:disable` (ADOPT-027, `crates/rustasea-cli/src/commands/modules.rs:72,137,164`), `make:module` (`crates/rustasea-cli/src/generators/kinds/module.rs`), `make:action` (`crates/rustasea-cli/src/generators/kinds/action.rs`), and `make:test --browser` (`crates/rustasea-cli/src/generators/kinds/test.rs`).

- **Goal**: 
Expand the `README.md` command documentation so it covers all 37 default registered CLI commands with their flags and options, and calls out the feature-gated `mcp:serve` command separately. Each entry must list the exact command signature and a one-line purpose traceable to the registering source file.

### 2. Step & Implementation

1. Rebuild the command reference table in `README.md` from `crates/rustasea-cli/src/commands/mod.rs` and `builtins.rs`, grouping entries by family: generators (`make:*`), module management (`module:*`), routing/introspection, database/migrations, queue, schedule, localization, logging, interactive, and feature-gated.
2. For each command record the signature and flags exactly as registered, for example `migrate:rollback [--step N]`, `queue:work [--queue=default] [--max-jobs=1]`, `lang:check [--locale=xx] [--path=resources/lang] [--json]`, and `log:show [--level=error] [--channel=daily] [--since=...] [--grep=text] [--limit=200] [--follow] [--json]`.
3. Add an explicit note that `mcp:serve` is gated behind the `mcp` cargo feature (`crates/rustasea-cli/src/commands/mod.rs:60-61`) and is only available when that feature is enabled.
4. Document the newer generator variants: `make:action`, `make:module`, and `make:test --browser`.
5. Add a short note that `tinker` (ADOPT-008) provides an interactive REPL, with usage pointing at the command source.
6. Cross-link the command table to `docs/milestones.md` M5 so the CLI surface and the milestone status stay in sync.

### 3. Acceptance & Verification

- **Checklist**: 
  - [ ] `README.md` documents all 37 default CLI commands plus the feature-gated `mcp:serve`.

  - [ ] No command is documented that does not exist in `crates/rustasea-cli/src/commands/mod.rs`.
  - [ ] The `mcp` feature gating of `mcp:serve` is stated explicitly.
