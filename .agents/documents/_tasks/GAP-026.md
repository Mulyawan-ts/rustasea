# [GAP-026] Laravel Parity Table Missing Recent Adoption Crate Status

### 1. Context & Analysis

- **Trigger**: 
The project tracks Laravel parity as a first-class deliverable, but the parity matrices have not been updated to reflect the ADOPT adoption wave. Several Laravel packages are marked "Planned" even though a corresponding crate is implemented, and most ADOPT milestones are absent from `docs/milestones.md`. This makes the parity picture look significantly less complete than the codebase actually is.

- **Observation**: 
`docs/laravel-parity.md:84` marks `Illuminate\Translation` as **Planned** with the note "No translator / locale loader". That is contradicted by `crates/rustasea-i18n`, whose module documentation states it is the analogue of `Illuminate\Translation` (milestone M3) and loads `resources/lang/{locale}/*.toml` or `*.json` with dot-namespaced keys and fallback locale. The `lang:check` command (ADOPT-005, `crates/rustasea-cli/src/commands/langcheck.rs:106`) is implemented as well. Other stale parity rows include `docs/laravel-parity.md:85` (`Illuminate\View` Planned, though `rustasea-view` and the `view` feature exist), `:86` (`Illuminate\Mail` Planned, though `rustasea-mail` exists), and `:98` (AI SDK described as deterministic stubs).

Beyond individual rows, the ADOPT coverage is incomplete. `docs/milestones.md` references only nine ADOPT IDs (014, 020, 023, 024, 025, 026, 027, 028, 029), while 31 exist (ADOPT-001 through ADOPT-031, all verified present in the tree). 22 of the 31 ADOPT implementations are either missing from `docs/milestones.md` or not cross-referenced in the parity matrices. Examples with implemented crates or commands: ADOPT-001 RBAC, ADOPT-002 activitylog, ADOPT-003 authlog, ADOPT-007 Sail/Docker, ADOPT-011 OpenAPI, ADOPT-021 Queue Dashboard, ADOPT-022 Broadcast (Redis/Pusher), ADOPT-025 SFTP, ADOPT-026 Google Auth, ADOPT-027 Modules, ADOPT-029 Browser, and ADOPT-031 Workspace Deps. The parity document references ten ADOPT IDs (014, 021, 022, 023, 024, 025, 026, 027, 028, 029). The user objective targets complete status for all 38 Illuminate packages and all 31 ADOPT milestones.

- **Goal**: 
Update `docs/laravel-parity.md` and `docs/milestones.md` so every one of the 38 Illuminate packages and every one of the 31 ADOPT milestones carries an accurate, current status with a `path:line` or crate reference, and so the two documents cross-reference the same ADOPT IDs.

### 2. Step & Implementation

1. Enumerate the ADOPT registry: list ADOPT-001 through ADOPT-031 with their title, owning crate or command, and implemented status. Use `crates/rustasea/Cargo.toml` feature comments, `crates/rustasea/src/lib.rs`, and command sources as evidence; where no registry document exists, create the mapping inside `docs/milestones.md` or a dedicated section.
2. Update `docs/laravel-parity.md` Table A rows: correct `Illuminate\Translation` (`:84`), `Illuminate\View` (`:85`), `Illuminate\Mail` (`:86`), the AI SDK row (`:98`), `Illuminate\Routing` (`:63`), and `HasMiddleware` (`:153`) to their implemented statuses with evidence; verify the remaining Illuminate rows against their crates.
3. Reconcile the Illuminate row count: the document currently has 49 data rows of which 43 begin with `Illuminate`; the objective target is 38 Illuminate packages. Either add the missing packages or document why the row set differs, so the stated total and the table agree.
4. Extend `docs/milestones.md` to reference all 31 ADOPT IDs, adding the 22 missing ones with their status and crate/command evidence, and cross-link each to the relevant milestone M0-M6.
5. Add a parity note that ADOPT adoption is tracked as a first-class input to the parity matrix and link the two documents.
