# [GAP-028] Missing Repository Root Governance and Hygiene Documents

### 1. Context & Analysis

- **Trigger**: 
The repository is positioned as an open-source framework intended for production adoption, yet it lacks the three root-level governance documents that such projects are expected to publish: a changelog, contribution guidelines, and a security policy. The absence is also an internal promise not kept: the roadmap commits to creating a changelog from milestone M0 onward, but the file was never created.

- **Observation**: 
No `CHANGELOG.md`, `CONTRIBUTING.md`, or `SECURITY.md` exists at the repository root (verified by directory listing). `.agents/documents/tasks/roadmap.md:22` states that migration notes will be tracked in `CHANGELOG.md` beginning at M0, and the release table at `roadmap.md:148` records "M0 | v0.1.0 | main | `CHANGELOG.md` created; migration guide empty baseline." Neither the M0 entry nor any later milestone produced the file. Meanwhile, the project completed milestones M0 through M6 (with M2 done and others partial) plus the ADOPT-001 through ADOPT-031 adoption wave, none of which is summarized in a release-facing changelog. Without `CONTRIBUTING.md`, the development workflow (`cargo xtask ci`, `cargo xtask migrate`, `cargo deny check`) and coding standards are only discoverable from scattered sources. Without `SECURITY.md`, there is no stated channel or process for reporting vulnerabilities.

- **Goal**: 
Create `CHANGELOG.md`, `CONTRIBUTING.md`, and `SECURITY.md` at the repository root. The changelog documents the M0-M6 and ADOPT-001..031 history; the contributing guide documents the development workflow, `xtask` commands, and coding standards; the security policy documents the vulnerability disclosure process.

### 2. Step & Implementation

1. `CHANGELOG.md`: adopt a Keep a Changelog style structure with an `[Unreleased]` section and dated milestone entries M0 through M6. Summarize the ADOPT-001 through ADOPT-031 adoption wave, grouping entries by crate or feature and noting the milestone each belongs to. Respect `docs/documentation-conventions.md`: reference milestones and dates, not raw commit SHAs.
2. `CONTRIBUTING.md`: document prerequisites and setup, the `xtask` surface (`ci`, `fmt`, `clippy`, `check-cycles`, `deps:check`, `migrate`, `docker:up`/`docker:down`/`docker:logs`), the test command (`cargo test --workspace`), the `cargo deny check` and `cargo audit` gates, the branch and commit conventions, and a pointer to the coding standards (including the 500-line file limit documented in `ADR-0009`).
3. `SECURITY.md`: document supported versions, the private disclosure channel, the expected response timeline, and the scope of in-scope components (framework crates, CLI, and adopted integrations such as auth, storage, and Google service-account handling).
4. Cross-link the three documents from `README.md` (Contributing section at `README.md:496+`) so they are discoverable.
5. Keep each file focused and under the repository line limit.

### 3. Acceptance & Verification

- **Checklist**: 
  - [ ] `CHANGELOG.md` exists at the repository root and covers M0-M6 and ADOPT-001..031.
  - [ ] `CONTRIBUTING.md` exists and documents the `xtask` surface, test, deny/audit gates, and coding standards.
  - [ ] `SECURITY.md` exists and documents versions, disclosure channel, and response expectations.
  - [ ] `README.md` links to all three documents.
  - [ ] No false version numbers or fabricated dates appear; entries reference milestones and real artifacts.

- **Testing**: 
  - [ ] Assert the three paths exist at the repository root.
  - [ ] For each `xtask` task named in `CONTRIBUTING.md`, confirm it is handled in `xtask/src/main.rs` (task dispatch and the `run_ci` sequence).
  - [ ] Verify every milestone and ADOPT ID mentioned in `CHANGELOG.md` corresponds to an artifact in the tree; assert no fabricated identifiers.
  - [ ] Confirm `README.md` contains working relative links to `CHANGELOG.md`, `CONTRIBUTING.md`, and `SECURITY.md`.
