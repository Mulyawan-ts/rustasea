# [GAP-023] Stale Documentation of route:list and Attribute Consumption

### 1. Context & Analysis

- **Trigger**: 
`README.md` and `docs/milestones.md` still describe two M1/M3 surfaces as incomplete: that `route:list` prints an empty table, and that declarative attributes (`#[middleware]`, `#[authorize]`) emit metadata constants that nothing consumes at runtime. Both statements were true at the time they were written but are now contradicted by the source tree. The stale prose understates implemented work and misleads contributors about where to invest effort.

- **Observation**: 
The route-table introspection path is fully wired. `crates/rustasea-cli/src/routes.rs:19` declares a process-wide `RouteSource` closure type, and `crates/rustasea-cli/src/routes.rs:33` (`set_route_source`) publishes it; `routes()` at `:52` reads it back. The runnable application publishes its live table at boot in `crates/rustasea-app/src/bootstrap/app.rs:57` (`rustasea::cli::routes::set_route_source(|| crate::routes::table().get_routes())`). `crates/rustasea-cli/src/commands/inspect.rs:44` (`let routes = routes::routes();`) renders that table through `inspect.rs:49-67` with six columns: Method, URI, Name, Action, Middleware, Binding. The empty-table and "until the router is wired" comments are gone from the code.

The declarative-attribute path is likewise wired at runtime. `#[middleware]` emits a doc-hidden `__RUSTASEA_MIDDLEWARE_<Fn>` const (`crates/rustasea-macros/src/lib.rs:89-95`), consumed by `Router::middleware_meta` at `crates/rustasea-router/src/metadata.rs:237`. `#[authorize]` emits `__RUSTASEA_AUTHORIZE_<Fn>` and resolves through `Router::authorize_meta` at `crates/rustasea-router/src/authorize.rs:216`. Dispatch applies them: `crates/rustasea-router/src/dispatch.rs:109` (`apply_middleware`) resolves specs through `MiddlewareRegistry`, and `dispatch.rs:135` (`apply_authorize`) wraps the route in an authorization layer. Job policy attributes (`#[tries]`, `#[backoff]`, `#[timeout]`) are also consumable now: `crates/rustasea-queue/src/policy.rs:4-5` documents `__RUSTASEA_TRIES_<Type>` / `__RUSTASEA_BACKOFF_SECS_<Type>` / `__RUSTASEA_TIMEOUT_SECS_<Type>`, bound at registration through `JobPolicy::from_seconds` as described in `crates/rustasea-queue/src/driver/worker.rs:57-60`.

Stale claims remain at `README.md:129` ("`route:list` still prints an empty table ... `inspect.rs:33`"), `README.md:151` ("still emit metadata consts that nothing consumes at runtime"), `README.md:170` (attributes marked "metadata only"), `docs/milestones.md:44` (empty table), `docs/milestones.md:46` and `:167` (no runtime consumer), `docs/milestones.md:95`, `:107-108`, and the P0 note at `docs/milestones.md:328-330`. `docs/laravel-parity.md:63` ("`route:list` introspection empty") and `:153` ("runtime consumer pending (GAP-003)") carry the same stale status.

- **Goal**: 
Update `README.md`, `docs/milestones.md`, and `docs/laravel-parity.md` to remove the obsolete "partial" / "empty table" / "unconsumed metadata" statements for `route:list`, `#[middleware]`, and `#[authorize]`, marking them implemented with accurate `path:line` evidence. Reconcile the `GAP-003` registry note so it records that the router/auth consumer landed.
